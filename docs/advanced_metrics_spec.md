# 进阶指标：怎么算、能说明什么

我们的仿真里，"人"是一段程序，按弹簧阻尼的规律对手里的板子出力；"机器人"是 PR2，靠测手腕上的力决定怎么动。板子两端一端是人、一端是机器人。每次运行都会以 50 Hz 记录一张完整的数据表：板的实际位置姿态、人出的力和力矩、机器人出的力和力矩、期望轨迹。下面 12 个指标除了特别说明的，都能从这张表算出来。

**1. 等性能人力减负率**
回答的问题是：加机器人之后，人省的力是不是真省了。做法：纯人、人机各跑一遍，分别记录人出的力和跟轨迹的误差。有个前提——必须先确认两次跟得差不多准，如果人机那次误差大很多，省力是假的（机器人摆烂了，任务没做好当然省力）。在误差相当的前提下，算（纯人时人的负担 − 人机时人的负担）÷ 纯人时人的负担，就是真正的减负比例。

**2. 协作增益**
和上一条类似但更粗一点：给每次运行打一个综合分（把跟得准不准、耗时、人费多大力加权合成一个数），看人机的团队分比纯人好了百分之几。它回答的是大方向的问题：加这个机器人，整体是赚是亏。如果增益是负的，机器人纯属拖后腿。

**3. 有效力比率**
人和机器人在板子上使的力，不会全部变成板子的运动——总有一部分被两端互相抵消掉了（人往东拽、机器人往西坠）。每个时刻把两端合力按板子的实际运动拆开，分成"干活的部分"和"互相抵消的部分"，后者占比越小，配合越好。我们一直怀疑的"人机对抗"，用这一个数字就能量化。

**4. 对抗功率占比**
和第 3 条是一对，但它带时间信息。每个时刻算人和机器人各自的功率（力乘上顺着力方向的速度）：顺着力动是正的，逆着力动是负的——负的意味着这一端在白使劲甚至被板子推回来。把两端互相顶牛的功率加起来占总功率的比例，就能精确指出**哪个时间段**在打架。比如 S22 转弯时人硬拽、机器人跟不上，那一段的对抗功率一定很高。

**5. 触觉沟通效率**
看机器人"读心"读得怎么样：用人的力变化去预测板子接下来零点几秒的运动，预测得越准、提前量越大、人用的力越小，沟通越高效。好的搭档轻轻一带就懂；差的搭档得死拉硬拽才有反应。"接下来该往哪走"不用人工标注——期望轨迹是我们自己定的，直接查表。

**6. 力—运动同步性**
把人端力和板子运动做频域分析：在各个频率上两者步调是否一致（相干度 0 到 1）、相位差多少。它的价值是能看见时域图上看不见的东西——比如我们之前发现的 2.4 Hz 垂直振荡，如果两端之力恰好在这个频率上反相，就说明它们是这个振荡的推手而不是受害者。对我们来说这条特别有用，垂直抖振和滚转抖振都能用它定量定位。

**7. 协作响应方向性**
滑动窗口算人和机器人运动之间的时间差：人动之后机器人多久跟上。统计下来如果全程都是人领先，机器人就是纯被动跟随；如果有时机器人领先，说明它有主动参与。真实世界里熟练搭档的领导权是流动的，这条指标量化的就是这件事。

**8. 人类协作基准距离**
需要一份"两个熟练真人一起搬东西"的数据做参照，然后看我们的人机协作在统计上离这个参照有多远。它不预设任何"好"的标准，直接问：像不像真人搭档。我们目前没有这种数据，暂时做不了，留给以后做真人实验。

**9. 表观阻抗/透明度**
人推板子时感觉到的"沉不沉、黏不黏"，学术上叫表观阻抗。理论上它应该等于板子本身的质量；如果机器人拖后腿，人会觉得板子比实际更沉、更难推动。算法是用板子的速度响应对人端力做拟合，得到等效的质量和阻尼，再和板子本体比较。需要给板子加持续的小激励才估计得准，只在人机条件下有意义。

**10. 扰动恢复代价**
在板子上突然加一个已知大小的推力，看它偏出去多远、多久回到轨迹附近、恢复期间人额外多费了多少力。平时误差小不代表稳——被撞一下之后是稳稳回来还是震荡半天、是不是恢复全靠人兜底，这个指标专门回答这个问题。在仿真里加扰动就是某一时刻多加一个力，是最容易补的实验。

**11. 累积人体工效暴露**
看人保持什么姿势、持重多久、关节受力多大，评估长期损伤风险。我们的虚拟人只是一个按弹簧规律出力的点，没有腰、肩、腕这些关节，所以这条在当前仿真里没有数据来源，只能留给以后的真人实验。

**12. 交互流畅度**
统计板子运动期间，人和机器人是不是同时在干活。"一个人动一步、另一个停着等"的时间占比越高越不默契；熟练搭档几乎同时启停，在轨迹拐点和姿态切换处差别最明显。

---

**汇总**：1、2、3、4、6、7、12 用现有的记录数据就能直接算；5 需要从期望轨迹生成"意图标签"、10 需要在仿真里加一个力脉冲、9 需要持续激励，都是很容易补的小改动；8 需要真人搭档的参照数据、11 需要人体模型，这两个目前的仿真给不了。
