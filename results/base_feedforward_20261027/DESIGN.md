# 在现有全身导纳QP中加入底盘运动参考

> 历史方案：这是用户澄清“已知底盘路径前馈”前形成的六维任务不变方案。它只能调整运动分配，不足以实现主动搬运。当前实验结构见 `ACTIVE_DESIGN.md`；后续真实运行结果见 `runtime_summary.json` 和 `REPORT.md`。本文件及最初运动学探针保留供追溯，不作为当前方案已完成的依据。

2026-10-27。当前阶段完成代码核对和隔离运动学验证，未修改生产控制器、coordinator、launch、摩擦模型或人端模型，未运行新增控制器的搬运实验。

## 目标与输入边界

底盘获得一个额外的平面运动参考，但末端六维任务仍由原导纳输出决定。默认延续机器人不读取虚拟人目标路径的实验边界；参考来源尚未确定。可以来自操作者独立输入、机器人交互力/运动状态估计，或经用户明确允许的外部规划器。用当前交互力生成参考属于反馈或意图估计，不应直接称为已经实现了预测前馈。

不把“保持导纳控制权”解释为固定末端姿态：人施加力矩时，末端仍应按原角导纳响应。此阶段优先保留完整六维任务，比仅保留角速度更接近原控制框架。

## 已确认的代码事实

- QP变量为 `u=[qdot_arm(7), vx_world, vy_world, wz]`，末端任务为 `J u ≈ v_adm`；当前 `W_ee=I, W_reg=.01I`，是加权软任务，不是硬等式。
- 当前正式搬运launch关闭 `posture_hold_enable`、pose tracking、orientation tracking。`freeze_orientation=False`，导纳角速度没有被人为锁死。
- `pr2_qp_whole_body_admittance.py` 约937行组装全身雅可比与QP，是底盘参考的合适接入位置。
- QP后还有底盘速度缩放、世界系到车体系转换和底盘XY滤波；正式配置 `cmd_vel_lpf_alpha=.10`。机械臂速度没有同步经历相同滤波，不能把未滤波的 `J u` 当作真实执行速度。
- coordinator按实际时间10Hz发送底盘和关节指令，QP解算100Hz。不能一边改变转发频率一边把变化都归因于底盘参考。
- 当前无有效wrench会把QP底盘速度上下界设为0。外部独立底盘参考若也希望在无wrench时运动，需要专门定义使能语义；不能无意绕过原有停止逻辑。

## 最小增量分配方案

第一步保持现有导纳和原QP不变，求出原解 `u0` 及其可实现末端速度 `v0=J u0`。

第二步解一个附加QP：

```
min  .5 ||E_base u - v_base_ref||^2_Wb + .5 epsilon ||u-u0||^2
s.t. J u = v0
     u_min <= u <= u_max
```

`E_base`选择后三维；底盘参考进入分配器，而不在coordinator或最终cmd_vel后直接叠加。机械臂相应补偿底盘引起的末端运动。任务不可同时满足时，底盘参考让步。

锁定的是原QP本来实现的六维速度，不是声称原有正则化残差已经消失。这样能先隔离验证“增加底盘偏好”这一个因素。后续若改为真正的分层QP，应先以笛卡尔误差为第一层，锁定其最优任务结果，再优化底盘与关节姿态；这是另外一项明确记录的控制器修改。

对于固定底盘速度，补偿关系为 `J_arm qdot_arm = v_adm - J_base v_base`，只在局部雅可比、速度限幅和可达性允许时成立。转向不只改变末端角速度，也通过末端相对底盘的力臂改变末端线速度，需使用完整六维雅可比。

严格任务优先级的背景：Escande等，2014，[Hierarchical quadratic programming](https://journals.sagepub.com/doi/10.1177/0278364914521306)；任务雅可比和冗余分配见[Stack of Tasks官方介绍](https://stack-of-tasks.github.io/documentation/a_introduction.html)。这类运动学优先级本身不证明接触动力学稳定、被动性或实际末端轨迹不变。

## 已运行的隔离验证

`kinematic_probe.py`加载当前生产XML和YAML中的初始关节角，用实际模型的末端雅可比求解。此处未推进动力学，未启动ROS节点，参考为人工构造的合成量，不使用人端目标。

雅可比秩6，10个速度变量，当前姿态下零空间维数4。

|场景|底盘参考|结果|
|---|---|---|
|末端任务为零，底盘X平移|0.05m/s|底盘约0.05m/s，机械臂补偿|
|末端任务为零，底盘Y平移|0.05m/s|底盘约0.049998m/s，机械臂补偿|
|末端任务为零，底盘偏航|0.10rad/s|底盘约0.10rad/s，机械臂补偿|
|合成的非零六维任务|[0.04,0.02,0.08]，单位m/s、m/s、rad/s|基本达到底盘参考，保持原任务速度|
|机械臂速度上限仅0.01rad/s|[0.2,0.2,0.4]|底盘大幅让步，仍保持原任务速度|

五个算例中相对原解的末端六维速度变化各分量绝对值均小于1e-7，且不违反速度界。原始解、直接叠加所引入的任务变化、模型源码哈希均保存在 `kinematic_probe.json`。这只能说明这个姿态下瞬时分配可行；不能推广到整条路径、关节极限、奇异姿态、摩擦接触或延迟下的实际控制表现。此处刻意隔离了正式代码的无wrench冻结逻辑，不能声称无力条件下生产底盘已经能自行运动。

复现：

source /workspace/pr2_ws/install/setup.bash

## 下一阶段的实际验证

1. 增加默认关闭的底盘参考接口，明确坐标系、时间戳、超时和限幅。先用合成小幅参考测试分配/补偿，再单独加入意图估计器，避免混淆两项改动。
2. 保持目前10Hz转发、导纳参数和摩擦场景不变，先完成开关对照；若现有滤波/执行误差影响明显，作为下一项单独干预处理。
3. 用同一组预设wrench输入验证导纳响应：检查新旧 `v_adm`、期望/实测末端twist、底盘实测速度，验证角导纳未被额外位置/姿态控制替代。不能只看木板是否“更平”。
4. 再跑真实闭环搬运S11/S22/S12和sinusoid，各至少3次交错运行；同时报告末端/木板姿态、轨迹误差、人端力与力矩、接触中断、关节余量和底盘参考误差。
5. 因额外底盘运动会改变接触力，闭环导纳输出和原轨迹可能合理变化。不能要求新旧时间序列逐点相同；应验证相同输入下的导纳映射，以及搬运任务中有没有实际改善和姿态代价。
6. 本次已知竖直重量主要由人承担；底盘运动参考不等于竖直承重控制，不能据此宣称减轻了承重负担。

只有隔离分配成功、真实执行补偿成立且整场重复对照有收益后，才可以称此方案对当前搬运有效。当前尚未完成这些动力学验证。
